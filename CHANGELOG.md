# FQLite 5.3

-  Headless library and command line (`./gradlew headlessJar`, package `fqlite.headless`): the recovery engine runs without GUI, JavaFX toolkit or display - `FQLiteHeadless.analyze(path)` returns tables and recovered records of the database, WAL archive and rollback journal (status, rowid, offset, flags, values, BLOB bytes) as Java objects, JSON or CSV; `java -jar fqlite-headless-5.21.jar --json out.json db`. Needs only javafx-base and antlr4-runtime at runtime; `publishToMavenLocal` publishes org.fqlite:fqlite-headless. To make this possible, the log window moved from AppLog to AppLogWindow, the Lighthouse dialog of Job to JobDialogs, and Job no longer posts to the JavaFX thread without a GUI (the CLI class MAIN now also runs without a JavaFX toolkit). See docs/HEADLESS.md
-  CASE/UCO export rewritten (CASE 1.5.0 / UCO 1.4.0, the output validates with case_validate from case-utils): every recovered record is an observable:ObservableObject with its state (live / deleted / deleted on a freelist page / old version of an UPDATE) and a RecoveredObjectFacet (recovered / partially recovered), every value an observable:TableField with TableFieldFacet (table, rowid, column, typed value, NULL); the offset in the source file is kept as DataRangeFacet; a case-investigation:InvestigativeAction links tool, examiner, source files (FileFacet, ContentDataFacet with MD5/SHA-1/SHA-256) and results, with the start and end of the analysis. Fixes: undefined kb: prefix (invalid identifiers), terms not defined in UCO (CyberItem, createdTime, toolVersion, ...), hashes of the database file reported for WAL / journal exports, local time without offset, platform-dependent file encoding; the output is streamed instead of built in memory. `./gradlew caseExportSample` writes a sample.
