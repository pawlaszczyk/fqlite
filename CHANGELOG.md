# FQLite 5.4 (in development)

-  JSONB (SQLite 3.45+): BLOBs in SQLite's binary JSON format (written by `jsonb()`, `jsonb_set()`, `jsonb_insert()`, `jsonb_patch()`, ...) are recognised and decoded - in live, deleted and WAL records. The table cell shows `[BLOB-n] JSONB {...}` (first 200 characters), tooltip, "Decode column into fields" and the BLOB viewer (double-click) show the JSON tree, the hex view keeps the raw bytes. The output is exactly what SQLite's `json()` returns, JSON5 elements (INT5, FLOAT5, TEXT5) included. JSONB has no magic number: a BLOB is taken for JSONB only if it is a complete, structurally valid array or object (scalars and one-byte values are not detected automatically, they would match too many other BLOBs). New: `fqlite.blob.Jsonb`, `BLOBTYPE.JSONB`, headless `RecoveryResult.getJson(record, column)`, `./gradlew jsonbTest`.
-  Large BLOBs / 64-bit values: serial types and payload lengths are read as 64-bit values. BLOBs and texts larger than ~1 GiB (serial type above 2^31; possible with SQLITE_MAX_LENGTH raised to its maximum of 2^31-1 and the 64-bit APIs such as `sqlite3_bind_blob64()`/`sqlite3_bind_zeroblob64()`) were not recognised before - the record was lost and its overflow pages showed up as garbage "deleted" records. They are now recovered completely (tested with 1.2 GB and 2.1 GB BLOBs). The overflow chain is read directly into the record buffer instead of being collected and copied twice, so a large BLOB needs about twice its size in heap (before: four times). A record that does not fit into the heap is skipped with a message (start with a larger `-Xmx`).
-  Rowids above 2^31 (e.g. timestamps or 64-bit ids as INTEGER PRIMARY KEY, common in messenger databases) were shown truncated/negative for live records (5000000000 → 705032704); rowids are now read as signed 64-bit varints.
-  Deleted records with overflow pages: the BLOB of such a record was stored under a wrong key (offset column index 2 instead of 0, "Number format exception: compute hash failed") - the BLOB was missing or belonged to another record; records near the end of a page whose local part could not be copied were dropped; an overflow chain that ended early dropped the whole record - now the readable part is kept and flagged "⚠ truncated".

# FQLite 5.3

-  Headless library and command line (`./gradlew headlessJar`, package `fqlite.headless`): the recovery engine runs without GUI, JavaFX toolkit or display - `FQLiteHeadless.analyze(path)` returns tables and recovered records of the database, WAL archive and rollback journal (status, rowid, offset, flags, values, BLOB bytes) as Java objects, JSON or CSV; `java -jar fqlite-headless-5.3.jar --json out.json db`. Needs only javafx-base and antlr4-runtime at runtime; `publishToMavenLocal` publishes org.fqlite:fqlite-headless. To make this possible, the log window moved from AppLog to AppLogWindow, the Lighthouse dialog of Job to JobDialogs, and Job no longer posts to the JavaFX thread without a GUI (the CLI class MAIN now also runs without a JavaFX toolkit). See docs/HEADLESS.md
-  CASE/UCO export rewritten (CASE 1.5.0 / UCO 1.4.0, the output validates with case_validate from case-utils): every recovered record is an observable:ObservableObject with its state (live / deleted / deleted on a freelist page / old version of an UPDATE) and a RecoveredObjectFacet (recovered / partially recovered), every value an observable:TableField with TableFieldFacet (table, rowid, column, typed value, NULL); the offset in the source file is kept as DataRangeFacet; a case-investigation:InvestigativeAction links tool, examiner, source files (FileFacet, ContentDataFacet with MD5/SHA-1/SHA-256) and results, with the start and end of the analysis. Fixes: undefined kb: prefix (invalid identifiers), terms not defined in UCO (CyberItem, createdTime, toolVersion, ...), hashes of the database file reported for WAL / journal exports, local time without offset, platform-dependent file encoding; the output is streamed instead of built in memory. `./gradlew caseExportSample` writes a sample.
