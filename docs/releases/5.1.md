# NodeQL for FQLite 5.1

This is a **source-only release of the NodeQL integration fork**. Download the
automatically generated **Source code (zip)** or **Source code (tar.gz)** below.
No prebuilt installers, bundled JRE, code-signing or notarization are included.
This is not an official release of the upstream FQLite project.

## Highlights

- Dedicated NodeQL graph icon in the FQLite toolbar.
- Updated visual editor with puzzle-shaped nodes, oval reporters, searchable
  categories and resizable panels, inspired by the current NodeQL application.
- Run queries and inspect results directly inside NodeQL; expand results when
  needed, with the SQL Analyzer remaining an optional hand-off.
- Light/Dark switch shared with the main FQLite application and result windows.
- Stable workspace while dragging, detaching, reattaching and zooming nodes.
- Live suggestions for tables, views and columns, respecting selected sources,
  aliases and ambiguous JOIN names. Custom SQL input remains available.
- Real checkbox multi-selection for columns: search, preselection, retained
  choices while filtering, Apply/Cancel and single-step Undo.
- Structured conditions, SELECT DISTINCT, aliases, ordering, LIMIT/OFFSET,
  nested reporters and SQLite-function expressions.

## Build and run

Use **JDK 21** and the included Gradle wrapper. After extracting the source:

```sh
./gradlew run
```

On macOS, `./run-fqlite.sh` can locate a compatible JDK 21 automatically.
On Windows, use `gradlew.bat run` with `JAVA_HOME` pointing to JDK 21.
Gradle downloads the build dependencies on the first run.

Open a SQLite database in FQLite, then click the NodeQL graph icon in the toolbar.
Use **☑** beside a column-list input for checkbox multi-selection.

## Verification

Validated with JDK 21 on macOS:

```sh
./gradlew --no-daemon compileJava processResources nodeQlSmokeTest
```

**199 JavaFX/SQLite checks passed**, including query execution, schema suggestions,
multi-selection, reporter Undo, camera stability, theme synchronization and
dialog cleanup. The smoke test requires a graphical desktop and uses only
generated sample data in an in-memory SQLite database.

## Scope and current limitations

- NodeQL workspaces are session-only: nodes are not saved or restored with FQLite
  project files. The shared theme selection also applies to the current session.
- This is a JavaFX integration, not the entire standalone NodeQL Flutter app.
- Native pointer automation, every legacy SQL template, other display densities
  and cross-platform installer packaging have not been exhaustively verified.
- The existing FQLite PDF manual is unchanged; the README and integration guide
  describe the updated NodeQL workflow.
